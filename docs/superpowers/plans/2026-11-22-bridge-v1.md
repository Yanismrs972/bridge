# Bridge v1 — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objectif :** un programme local qui, depuis une page web, mène un projet de bout en bout. Il passe par un entretien, un plan, puis une boucle par tâche : Codex écrit la consigne, Claude exécute, l'orchestrateur collecte les preuves, Codex évalue. Il ne s'arrête que pour les décisions humaines.

**Architecture :**
- Deux couches dans un même processus Node.
- `src/bridge/` lance les CLI et normalise leurs sorties, sans aucune décision.
- `src/orchestrator/` détient toute la logique : états, limites, preuves, permissions, SQLite.
- `src/server/` expose une API HTTP locale protégée par jeton et sert la page statique `web/`.
- Le code de lancement de processus vient d'Agent Bridge (MIT). Les arguments CLI verrouillés et les contrôles d'événements viennent du harnais Phase 0A.

**Pile technique :** TypeScript 5.9, Node ≥ 22.13, `node:sqlite`, `zod@4.4.3` (seule dépendance d'exécution), `tsx` et `node --test` pour les tests, Playwright (préinstallé) pour le test bout en bout.

**Spécification :** `docs/superpowers/specs/2026-11-18-bridge-orchestrateur-design.md` (validée par l'utilisateur). Les références §N renvoient à ce document.

**Sources à recopier :**
- Agent Bridge : cloner `https://github.com/jcharveyjr/claude-chatgpt-agent-bridge` (commit du 23/07/2026) dans le dossier temporaire de la session.
- Harnais Phase 0A : `harness/run-phase0a.mjs` de ce dépôt.

## Contraintes globales

- Node ≥ 22.13 (`"engines": {"node": ">=22.13"}`). Aucune dépendance d'exécution autre que `zod` ; dépendances de développement : `typescript`, `tsx`, `@types/node`.
- Écoute **uniquement** sur `127.0.0.1`, port par défaut `8790`.
- Racine des projets par défaut : `path.join(os.homedir(), 'BridgeProjets')`. Tout chemin hors de cette racine est refusé.
- Codex ne reçoit **jamais** de permission d'écriture. L'adaptateur Codex refuse une requête avec `write: true` sans lancer de processus.
- Aucune clé API transmise aux agents. Filtre d'environnement = `STRIP_ENV` du harnais, recopié à l'identique.
- Jamais de `git push`, de `git remote add`, ni de dépôt distant configuré par Bridge.
- Une tentative est enregistrée `dispatched` en base **avant** le lancement du processus. Au démarrage, toute tentative `dispatched` ou `running` devient `unknown` et n'est jamais relancée seule.
- Un seul agent tourne à la fois, tous projets confondus.
- Limites :
  - 8 appels Codex par tâche, 80 par projet, 30 par jour (jour local, tous projets confondus) ;
  - 3 cycles de correction par tâche ;
  - 20 tours et 0,50 USD par exécution de Claude ;
  - délais de 5 min par appel Codex et de 15 min par appel Claude ;
  - 2 répétitions consécutives (même diff ou même erreur) → escalade ;
  - 1 nouvel essai sur une sortie non conforme au schéma, puis escalade ;
  - 3 tours d'entretien au maximum ;
  - extrait de diff limité à 200 lignes.
- Les valeurs `usage` ne sont jamais inventées : `measured`, `estimated` ou `unavailable` (§8).
- Les textes visibles par l'utilisateur (page, messages d'erreur, prompts) sont en français. Les identifiants de code sont en anglais.
- Les fichiers repris d'Agent Bridge gardent en tête : `// Adapté de jcharveyjr/claude-chatgpt-agent-bridge (MIT, © 2026 JC Harvey)`.

## Points d'attention pour la revue

Ce sont les cas que la spécification implique sans que les tests de base les couvrent. Chacun a un test ajouté dans la tâche indiquée.

1. **Chemin de projet piégé** : un nom de projet avec `..`, `/`, `\`, un nom réservé Windows (`con`, `nul`…) ou une chaîne vide doit être refusé avec un message clair, jamais créer un dossier hors de la racine. → Tâche 3, `rejects unsafe project names`.
2. **Codex qui modifie quand même le projet** : si `git status --porcelain` diffère avant et après un appel Codex, la mission s'arrête et une alerte s'affiche. → Tâche 9, `stops mission when supervisor changes the tree`.
3. **Claude qui demande une commande hors liste** : la commande est refusée par le CLI, l'appel n'est **pas** tué, et la page en garde trace. En revanche, un outil interdit (`WebFetch`, `mcp__*`…) tue l'appel. → Tâche 5, `records denied bash command without killing`.
4. **Fermeture de la page ou du PC en pleine exécution** : au redémarrage, la tâche est `needs_review` avec le diff affiché, et trois choix sont proposés. → Tâche 10, scénario `recovery`.
5. **Réponse du superviseur valide mais incohérente** : un `accept` alors qu'une commande de vérification échoue devient une escalade. Un `correct` sans `correction` est traité comme une sortie non conforme. → Tâche 9, `downgrades accept when verification fails`.
